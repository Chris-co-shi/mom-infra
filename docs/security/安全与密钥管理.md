# 安全与密钥管理

## 1. 目标

为 local、dev、test、prod-like 建立一致的基础安全边界，重点防止凭证泄露、过度授权、管理端口暴露和供应链漂移。

## 2. Secret 原则

- Git 中禁止出现明文密码、Token、私钥和完整连接凭证。
- Manifest 只引用 Secret 名称和 Key。
- Secret 的生成、加密、解密、轮换和销毁必须有 Runbook。
- 不同环境使用不同凭证，禁止复制 prod-like 凭证到低环境。
- CI 不输出解密后的 Secret。
- 备份中的 Secret 或配置也必须加密。

## 3. 候选方案

Phase 01 需要在以下方案中完成 ADR 决策：

| 方案 | 优点 | 风险 |
|---|---|---|
| SOPS + age | GitOps 友好、离线可用、易审查 | 需要管理 age 私钥和轮换 |
| External Secrets | 与外部密钥服务集成 | 本地环境和外部依赖更复杂 |
| 手工创建 Secret | 简单 | 漂移、不可审查、难恢复 |

手工 Secret 只能作为临时 PoC，不作为长期方案。

## 4. RBAC 与 ServiceAccount

- 每个应用或组件使用独立 ServiceAccount。
- 默认不授予集群管理员权限。
- Namespace 内权限优先于 ClusterRole。
- 运维脚本不得默认使用长期高权限 Token。
- CI 部署身份与人工运维身份分离。
- 权限变更需要记录原因和影响范围。

## 5. 网络边界

- 数据库、中间件管理端口默认只允许集群内部访问。
- 外部入口统一通过 Ingress 或受控管理通道。
- 管理控制台不直接暴露公网。
- 后续通过 NetworkPolicy 明确应用到 PostgreSQL、Redis、Nacos、RocketMQ、Seata 和观测组件的允许关系。
- 故障演练不得绕过长期安全边界后忘记恢复。

## 6. TLS 与证书

- Ingress 使用 TLS。
- 证书来源、有效期和轮换方式必须记录。
- 私钥不得进入 Git。
- 证书更新需要验证应用连接、Webhook 和管理入口。
- 证书过期应有提前告警。

## 7. 镜像与供应链

- 禁止使用 `latest`。
- test/prod-like 使用固定版本，关键镜像使用 Digest。
- 记录镜像仓库、上游项目和许可证。
- 限制从未知公共仓库直接拉取镜像。
- 后续引入镜像漏洞扫描和 SBOM。
- 第三方 Chart 或 Manifest 修改必须记录来源和 Diff。

## 8. 敏感日志

禁止记录：

- 密码、Refresh Token、API Key。
- 私钥和完整证书内容。
- 数据库连接串中的密码。
- 用户隐私和真实生产数据。

日志脱敏由应用和基础设施共同负责；Collector 不应被视为唯一脱敏层。

## 9. 安全校验门禁

CI 应逐步加入：

- 常见私钥和凭证模式扫描。
- 禁止明文 Kubernetes Secret 值。
- 禁止浮动镜像 Tag。
- 高权限 RBAC 检查。
- hostNetwork、privileged、hostPath 等高风险配置检查。
- 镜像来源白名单。

## 10. 事件处置

发现凭证泄露时：

1. 立即停止继续使用该凭证。
2. 轮换并撤销旧凭证。
3. 检查 Git 历史、CI 日志和制品。
4. 判断是否需要清理 Git 历史。
5. 检查访问日志和异常行为。
6. 记录影响、处置和改进措施。

仅删除当前文件并不能消除 Git 历史中的泄露。
