# 运行手册规范

运行手册（Runbook）用于指导可重复执行的运维操作。它不是架构说明，也不是命令备忘录。

## 1. 适用范围

以下操作必须有 Runbook：

- 集群初始化和节点替换。
- 中间件部署、升级和回滚。
- 证书更新。
- PostgreSQL 备份、恢复和故障处理。
- Redis 持久化、故障切换和恢复。
- Nacos、RocketMQ、Seata 故障恢复。
- OpenTelemetry、Prometheus、Loki、Tempo、Grafana 排障。
- 应用滚动升级和回滚。
- 存储压力、节点故障和网络异常处置。

## 2. 标准结构

```markdown
# 操作名称

- 状态：Draft / Verified / Deprecated
- 适用环境：local / dev / test / prod-like
- 最后验证日期：YYYY-MM-DD
- 负责人：
- 预计影响：

## 目标
## 前置条件
## 风险与影响范围
## 停止条件
## 执行步骤
## 技术验证
## 业务验证
## 回滚或恢复
## 证据留存
## 已知限制
## 复盘记录
```

## 3. 前置条件

必须说明：

- 所需权限。
- 所需工具版本。
- 当前组件和目标组件版本。
- 备份或恢复点是否存在。
- 依赖服务是否健康。
- 操作窗口和通知对象。

禁止使用“确保环境正常”等模糊描述，应给出具体检查命令和成功判定。

## 4. 风险与影响范围

至少描述：

- 影响的 Namespace、服务和用户。
- 是否导致写入暂停。
- 是否可能丢失未持久化数据。
- 是否影响 Trace、Log、Metric 采集。
- 最坏情况下的恢复方式。

## 5. 停止条件

出现以下情况应停止继续操作：

- 当前状态与 Runbook 前置条件不一致。
- 备份或恢复点不可用。
- 健康检查持续恶化。
- 数据校验出现不可解释差异。
- 管理通道可能失联。
- 回滚条件已经满足。
- 操作超出预定爆炸半径。

## 6. 验证

技术验证包括：

- Pod/Node/Service/Endpoint 状态。
- Readiness/Liveness。
- 日志错误率。
- 指标和 Trace。
- 数据库连接和复制状态。
- MQ 生产消费与堆积。

业务验证包括：

- 登录或 Token 获取。
- 关键 API。
- 消息事件闭环。
- 数据写入和查询。
- PCS/WCS 命令和回执。

只有 Pod Running 不代表业务恢复。

## 7. 回滚与恢复

每份 Runbook 必须明确：

- 回滚触发条件。
- 可回滚版本。
- 配置回滚方式。
- 数据迁移是否可逆。
- 回滚后如何验证。
- 无法回滚时如何从备份恢复。

## 8. 证据留存

建议保留：

- 执行开始和结束时间。
- 关键命令输出。
- 事件和日志片段。
- Grafana 截图或查询链接。
- 变更前后版本。
- 数据校验结果。
- 实际 RTO/RPO。
- 异常和人工决策。

证据不得包含明文密码、Token、私钥和敏感业务数据。

## 9. 状态管理

| 状态 | 含义 |
|---|---|
| Draft | 已编写但未完整执行 |
| Verified | 已在指定环境成功验证 |
| Needs Review | 环境或版本变化后需要复核 |
| Deprecated | 已不再适用 |

版本、拓扑或关键命令发生变化时，Verified 状态应重新评估。
