# 文档维护约定

本文档定义 `mom-infra` 的文档分支、中文命名方式、内容结构和 PR 要求。

## 1. 分支策略

文档必须与其描述的实现保持在同一条变更链路中：

- 与 Manifest、脚本、CI、配置同时变化的文档，必须放在同一个 Feature 分支和同一个 PR。
- 纯文档整理使用 `docs/<topic>` 分支。
- ADR、计划和 Runbook 不使用长期固定分支，避免文档与实现分离。
- 禁止直接在 `main` 修改文档或基础设施配置。

示例：

```text
feat/infra-phase01a-foundation-gates
feat/postgresql-local-poc
docs/restore-runbook-template
```

## 2. 标准流程

```text
同步 main
→ 创建本次变更分支
→ 同步修改实现与关联文档
→ 检查链接、Mermaid、命令和现状描述
→ 创建 Draft PR
→ 等待 CI 与审查
→ Squash merge
```

## 3. 命名方式

- 文档文件名优先使用中文。
- 一级目录保留英文，兼顾脚本、链接和跨平台工具。
- ADR 保留编号前缀，例如 `ADR-005-组件版本与镜像锁定.md`。
- 阶段计划保留 Phase 编号，例如 `Phase-01-基础设施计划.md`。
- 禁止使用 `临时.md`、`其他.md`、`说明.md` 等无明确语义的名称。

## 4. 现代化文档风格

文档应保持：

- 中文表达清晰。
- 标题层级明确。
- 适度使用状态提示、表格、Mermaid 和代码块。
- 先说明目标和边界，再给出实施与验收。
- 对风险、失败路径和回滚保持显式描述。
- 不用装饰掩盖尚未实现的事实。

## 5. 运行手册要求

每份 Runbook 至少包含：

1. 目标。
2. 适用环境。
3. 前置条件。
4. 风险和影响范围。
5. 执行步骤。
6. 健康与业务验证。
7. 回滚或恢复步骤。
8. 证据留存。
9. 升级条件和停止条件。

## 6. 文档一致性

- 根 README 是入口，不是全部事实来源。
- 组件版本以 `config/component-versions.yaml` 为权威来源。
- 环境差异以 Overlay 为权威来源。
- 架构决策以 ADR 为权威来源。
- 运行步骤必须与脚本、Manifest 和实际命令保持一致。
- 当代码或配置尚未实现时，必须标记为“计划中”或“待验证”。
- PR 中实现变化但关联文档未更新时，不允许合并。
