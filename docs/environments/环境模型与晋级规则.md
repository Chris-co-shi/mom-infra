# 环境模型与晋级规则

## 1. 环境定义

| 环境 | 目的 | 数据策略 | 拓扑要求 | 允许的中断 |
|---|---|---|---|---|
| `local` | 单人开发与 Manifest 验证 | 可丢弃 | 单节点可接受 | 随时重建 |
| `dev` | 多服务共享集成 | 可重建，保留必要样例 | 简化拓扑 | 短时中断可接受 |
| `test` | 端到端、性能和故障测试 | 定期备份 | 模拟关键高可用结构 | 需受控 |
| `prod-like` | 面试演示和生产模拟 | 受保护并验证恢复 | 三节点 k3s | 按 Runbook 处理 |

`prod-like` 不是实际生产环境，不处理真实业务数据，但需要尽可能模拟生产部署、观测、升级和恢复过程。

## 2. 配置分层

```text
kubernetes/base
      ↓
environments/local
      ↓
environments/dev
      ↓
environments/test
      ↓
environments/prod-like
```

实际实现并不是逐级继承 Overlay，而是所有环境引用共同 Base。上图表示晋级顺序。

Base 中保存：

- 通用 Namespace。
- 通用标签和资源名称。
- 服务与基础资源结构。
- 环境无关的探针和端口。

Overlay 中保存：

- 副本数。
- 资源请求和限制。
- StorageClass 与容量。
- 域名与 Ingress。
- 日志级别和采样率。
- Secret 名称和外部引用。
- 高可用和调度差异。

## 3. 晋级门禁

### local → dev

- Kustomize 渲染成功。
- YAML 与脚本校验通过。
- 无明文 Secret、私钥或 `latest` Tag。
- 基础 Pod 能启动并通过 Readiness。

### dev → test

- 服务间联调完成。
- 资源请求和限制已配置。
- 持久化和数据初始化可重复。
- Metrics、Logs、Traces 可查询。
- 关键配置和版本已锁定。

### test → prod-like

- 镜像使用固定版本，关键镜像使用 Digest。
- PostgreSQL 和 Redis 恢复测试通过。
- 滚动升级与回滚演练通过。
- 节点故障与至少一个中间件故障演练通过。
- 运行手册、停止条件和证据齐全。
- 不存在未评审的高风险临时配置。

## 4. 配置漂移

以下行为视为漂移：

- 直接 `kubectl edit` 修改长期配置。
- 手工创建未进入 Git 的资源。
- 修改在线 Secret 后不更新 Secret 权威源。
- 在节点上直接修改容器或中间件文件。
- 通过 UI 修改 Grafana、Nacos 等配置而不导出回库。

漂移处理：

```text
发现差异
→ 判断线上临时处置是否有效
→ 将有效修改转为 Git 变更
→ 通过校验与 PR
→ 重新部署并确认一致
```

紧急变更可先在线执行，但必须记录时间、操作者、原因、影响和回写任务。

## 5. 环境数据

- `local` 使用脚本生成的可丢弃样例数据。
- `dev` 使用共享模拟数据，不含真实敏感数据。
- `test` 使用可重置的端到端测试数据集。
- `prod-like` 使用完整演示数据，但不使用真实客户、供应商和生产数据。
- 环境之间禁止直接复制真实凭证。

## 6. Secret 差异

Git 只保存：

- Secret 名称。
- Key 名称。
- 加密文件或外部 Secret 资源定义。
- 生成和轮换说明。

Git 不保存：

- 明文密码。
- 私钥。
- 未加密 Token。
- 数据库完整连接串中的密码。

## 7. 回退规则

环境晋级失败时：

1. 停止继续向更高环境晋级。
2. 保留失败日志、事件和 Trace。
3. 回退到上一已验证版本或恢复点。
4. 判断是应用、配置、基础设施还是数据迁移问题。
5. 修复后从失败环境重新验证，不跳过门禁。

## 8. 验收

- 四套 Overlay 均能独立渲染。
- Base 未包含环境专属域名、密码或固定节点地址。
- 环境差异有清晰 Diff。
- `prod-like` 不使用浮动镜像 Tag。
- 变更晋级和回退均有可执行命令与证据。
