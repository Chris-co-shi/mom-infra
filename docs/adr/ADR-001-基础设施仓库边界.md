# ADR-001：基础设施仓库边界

- 状态：Accepted
- 日期：2026-07-18
- 关联文档：[仓库边界](../architecture/仓库边界.md)

## 1. 背景

MOM 项目包含后端、PCS、WCS、Web、PDA、模拟器和基础设施多个仓库。若部署资源、中间件配置和业务代码混在一起，环境治理、回滚和权限边界会变得模糊。

## 2. 候选方案

### 方案 A：部署配置跟随各应用仓库

优点：应用与部署文件距离近。

缺点：共享中间件、环境 Overlay 和运维规则分散，难以统一审查和恢复。

### 方案 B：独立 `mom-infra` 仓库

优点：基础设施变更独立审查，环境和运行手册集中治理。

缺点：应用仓库必须提供明确运行契约，并保持跨仓库协同。

## 3. 决策

采用方案 B。`mom-infra` 是共享基础设施、环境配置和运维程序的权威来源；应用仓库拥有镜像构建、业务行为和领域契约。

## 4. 后果

正向：

- 基础设施变更可独立审查和回滚。
- 环境漂移更容易识别。
- 中间件、观测、安全和容灾规则可以统一。

负向：

- 需要维护应用运行契约。
- 跨仓库版本协调成本增加。

## 5. 实施约束

- `mom-infra` 不复制应用源码。
- 业务数据库 DDL 归应用仓库所有。
- 领域消息 Payload 不在本仓库定义。
- 应用仓库必须提供镜像、端口、探针、配置和资源基线。

## 6. 验证

每个新服务接入前完成运行契约检查，确认基础设施仓库无需理解业务内部实现即可部署、观测和回滚该服务。
