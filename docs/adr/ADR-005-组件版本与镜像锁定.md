# ADR-005：组件版本与镜像锁定

- 状态：Accepted
- 日期：2026-07-18
- 关联文档：[Phase 01 基础设施计划](../plans/Phase-01-基础设施计划.md)

## 1. 背景

基础设施依赖大量第三方组件。若使用浮动 Tag、未登记 Chart 或不明确镜像来源，相同 Git Commit 在不同时间可能部署出不同结果。

## 2. 候选方案

### 方案 A：使用 `latest` 或自动跟随最新版

优点：维护简单。

缺点：不可重复、不可预测、回滚困难。

### 方案 B：锁定版本，不锁定 Digest

优点：可读性和可维护性较好。

缺点：部分镜像仓库可能重新发布相同 Tag。

### 方案 C：版本目录 + test/prod-like 关键镜像 Digest

优点：可重复、可审计、便于回滚。

缺点：升级流程和维护成本增加。

## 3. 决策

采用方案 C。所有组件在 `config/component-versions.yaml` 登记精确版本、上游地址和来源；test/prod-like 的关键镜像使用 Digest 锁定。

## 4. 实施约束

- 禁止 `latest`、`stable`、`edge` 等浮动 Tag。
- Chart、Operator、Manifest 和镜像版本必须可追踪。
- 升级必须经过兼容性验证和回滚准备。
- 组件版本目录与 THIRD-PARTY-NOTICES 保持一致。
- 不允许仅在运维终端记录版本而不进入 Git。

## 5. 后果

正向：

- 同一 Git 版本可重复部署。
- 供应链和许可证更容易审查。
- 故障时可明确回退目标。

负向：

- 升级需要主动维护版本和 Digest。
- local/dev 与 prod-like 可能需要不同镜像策略。

## 6. 验证

- CI 拒绝浮动 Tag。
- 版本目录不存在未说明的 `pending`。
- 能从版本目录定位每个组件的上游来源和许可证。
- 完成一次组件升级与回滚演练。
