# ADR-003：密钥不得明文进入 Git

- 状态：Accepted
- 日期：2026-07-18
- 关联文档：[安全与密钥管理](../security/安全与密钥管理.md)

## 1. 背景

基础设施仓库需要保存可重复部署的配置，但密码、Token、私钥和证书私钥一旦进入 Git，即使删除当前文件，仍可能留在历史、CI 日志和缓存中。

## 2. 候选方案

### 方案 A：提交明文 Secret

优点：最简单。

缺点：不可接受的泄露风险，无法满足开源仓库要求。

### 方案 B：人工在每个环境创建 Secret

优点：无需加密工具。

缺点：不可审查、漂移严重、难以重建和轮换。

### 方案 C：加密文件或外部 Secret 管理

优点：兼顾 GitOps、审查与安全。

缺点：需要管理密钥、工具和恢复流程。

## 3. 决策

采用方案 C。Git 只保存 Secret 引用、Key 名称、加密材料或外部 Secret 定义。Phase 01 必须在 SOPS+age 和 External Secrets 等方案中完成最终选型。

## 4. 实施约束

- 禁止提交明文密码、Token、私钥和生成后的 Secret Manifest。
- 不同环境使用不同凭证。
- CI 不输出解密结果。
- 密钥生成、分发、轮换、撤销和恢复必须有 Runbook。
- 临时手工 Secret 仅允许 PoC，并必须记录漂移和清理计划。

## 5. 后果

正向：降低凭证泄露和环境不可重建风险。

负向：增加密钥工具、人员权限和恢复管理成本。

## 6. 验证

- CI 能识别常见私钥和凭证模式。
- 仓库 Manifest 不包含真实 Secret 值。
- local/dev 能通过受控流程注入凭证。
- 完成一次密钥轮换和恢复演练。
