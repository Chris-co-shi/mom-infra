# 仓库边界

## 1. 本仓库负责

- k3s 与 Kubernetes 资源组织。
- 中间件和可观测性部署配置。
- 环境 Overlay 与晋级规则。
- Ingress、TLS、NetworkPolicy、RBAC 和 Secret 引用约定。
- 资源请求、限制、亲和性和健康检查。
- 备份、恢复、升级、回滚和故障演练自动化。
- 基础设施校验、运行手册和恢复证据。

## 2. 本仓库不负责

- Java、Python、TypeScript、Vue 或 uni-app 业务源码。
- 业务服务拥有的数据库 DDL。
- 领域消息 Topic 和事件 Payload 定义。
- PCS/WCS 设备状态机和协议实现。
- Web/PDA 原型图。
- 应用内部权限、幂等和事务实现。

## 3. 应用仓库向本仓库提供的运行契约

每个可部署服务至少应提供：

| 契约 | 示例 |
|---|---|
| 镜像坐标 | `ghcr.io/example/mom-gateway:<version>` |
| 容器端口 | `8080` |
| 健康检查 | `/actuator/health/liveness`、`/readiness` |
| 指标端点 | `/actuator/prometheus` |
| OTLP 配置 | Endpoint、协议、服务名 |
| 配置依赖 | Nacos、环境变量、Secret 名称 |
| 数据依赖 | PostgreSQL Schema、Redis、RocketMQ |
| 资源基线 | CPU、内存、临时存储 |
| 启停语义 | 优雅停机时间、启动依赖 |
| 数据迁移 | Flyway 执行边界 |

## 4. 典型职责划分

| 场景 | 应用仓库 | mom-infra |
|---|---|---|
| 新增配置项 | 定义含义和默认行为 | 注入环境值与 Secret 引用 |
| 数据库变更 | 提供 Flyway Migration | 提供数据库与权限，不修改业务表 |
| 新增 MQ Topic | 定义业务语义 | 提供 Broker 和资源创建机制 |
| 增加链路追踪 | 应用埋点与业务关联 | Collector、Tempo 和 Grafana |
| 调整资源 | 提供性能证据 | 更新 Overlay 并验证调度 |
| 服务故障 | 提供应用恢复语义 | 执行重启、扩容、回滚和证据收集 |

## 5. 禁止事项

- 在 `mom-infra` 复制应用源码。
- 为方便查询而跨服务修改业务 Schema。
- 将真实凭证写入 Values、Manifest 或脚本。
- 直接在集群中修改配置而不回写 Git。
- 由基础设施脚本猜测应用业务状态。
- 在没有应用版本和回滚镜像时执行升级。

## 6. 验收

新应用接入 `mom-infra` 前，必须完成运行契约评审，并证明：

1. 镜像可重复构建。
2. 健康检查能区分存活与就绪。
3. 关闭过程不会立即丢失正在处理的请求或消息。
4. 配置与 Secret 来源明确。
5. 指标、日志和 Trace 可关联。
6. 资源基线有测试证据。
7. 数据迁移与回滚边界明确。
